# 重构中的NwayPBX


		<a href="98.html"><h1>重构中的NwayPBX</h1></a>
                <br/><b>                <p>自从第一版NwayPBX测试版发行，我们也遇到了非常多的难题，诸如：</p>
<ol>
<li>
<p>接口相对比较难做，只能以socket通信或数据库查询方式，在当下相对难以适应新的需求</p>
</li>
<li>
<p>C系列语言的依赖与编译较麻烦，且和自身的管理系统部分要结合比较吃力</p>
</li>
<li>
<p>代码量巨大，在进行新的扩与改，耗费的精力比较多</p>
</li>
<li>
<p>在条件不成熟，或者说尽量避免使用所谓“云平台”</p>
</li>
</ol>
<p>痛定思痛，在经过两年时间的NwayPBX客户使用后，还是决定完全重构整个系统。</p>
<p>整个系统完全采用Golang作为中间件，接口，web的开发语言，以保证整个系统的高性能受损小，而能解决以上所阐述的难题。</p>
<p>在使用Inbound处理接口，Outbound做路由处理，Redis做缓存处理，再经过对FreeSWITCH进行一定的Bug改进，那么FreeSWITCH在性能和功能上的优异性就可以体现出来了。</p>
