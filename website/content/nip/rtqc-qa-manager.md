## 1. 产品概述

### 1.1 产品简介

RT-QC 质检平台是一套**实时通话语音质检系统**：通话语音经前端抓包与 VAD（语音活动检测）切分后送入 ASR 语音识别集群转写成文字，平台按照预先配置的质检规则对转写文本进行实时匹配，命中后按规则执行"记录 / 告警 / 挂断"等动作，并可把命中通知推送到企业微信群。所有通话、转写文本、命中记录、CPD 号码检测结果均可在平台上查询、复盘和导出。

### 1.2 核心能力

- **实时转写**：对接 NASR 语音识别集群，通话双方语音按对话轮次实时转写为文本。
- **实时质检**：支持关键词与正则表达式两类规则，可限定坐席侧/客户侧，按优先级逐条匹配。
- **动作联动**：命中可仅记录、告警通知，或对高危通话（如诈骗、辱骂）执行实时挂断联动。
- **企业微信通知**：命中后自动推送群机器人消息（可 @ 指定成员、聚合去重、限流）。
- **通话复盘**：在线查看通话双方"聊天气泡式"转写、播放录音、对照命中规则与匹配原文。
- **CPD 号码检测**：展示空号、停机、拒接、回铃等号码状态检测结果与评分、相似度。
- **运营监控**：活跃通话、ASR 请求量与成功率、NASR 集群健康度、授权与计费状态实时看板。
- **多语言**：支持中文、English、日本語、한국어、Español、Português 六种界面语言。

### 1.3 业务处理流程

```
通话语音抓包(nip)
        │
        ▼
  VAD 语音切分
        │
        ▼
 NASR 集群 ASR 转写 ──► 转写文本（分坐席侧/客户侧、按轮次累积）
        │
        ▼
 质检规则引擎匹配（启用规则按优先级升序，同一通同一侧同一规则只命中一次）
        │
        ├─ 记录落库：通话记录 / 质检命中 / 号码状态
        ├─ 企微群通知（规则开启"企微推送"时）
        └─ 挂断联动：动作为"挂断(hangup)"时，通知前台执行挂机
```

### 1.4 名词解释

| 名词 | 含义 |
| --- | --- |
| ASR | Automatic Speech Recognition，自动语音识别（把语音转成文字） |
| NASR | 本平台对接的 ASR 识别服务集群，可配置多个实例做负载分担 |
| CPD | Call Progress Detection，通话状态/号码状态检测（空号、停机、彩铃等） |
| VAD | Voice Activity Detection，语音活动检测，用于把通话切成语音片段 |
| 坐席侧 / A-Leg | 本端/主叫一侧的语音（如外呼系统侧） |
| 客户侧 / B-Leg | 对端/被叫一侧的语音（客户电话侧） |
| 命中 | 通话文本匹配到了某条质检规则 |
| 规则动作 | 命中后的处理方式：记录/告警/挂机/警告/通知/阻断（详见 3.2.3） |
| 门控 | 授权与计费总开关；欠费或离线宽限耗尽时平台将暂停实时质检 |

## 2. 登录与界面布局

### 2.1 登录

在浏览器打开管理地址，进入登录页：

![登录页](images/login.png)

操作步骤：

1. 输入**用户名**、**密码**。
2. 输入右侧图形**验证码**（4 位字符，不区分大小写；看不清可点击图片刷新）。
3. 点击「登 录」，成功后自动进入仪表盘。

安全机制说明：

- 验证码**一次性有效**，有效期约 5 分钟；登录失败后验证码自动刷新。
- 同一账号连续输错密码 **5 次将锁定 30 分钟**，登录接口另有每 IP 每分钟 5 次的频率限制。
- 登录状态（会话）有效期为 **2 小时**，超时后自动跳回登录页。
- 系统出厂内置三个账号（首次登录请立即修改密码）：

| 用户名 | 角色 | 出厂初始密码 | 用途 |
| --- | --- | --- | --- |
| admin | 超级管理员 | Admin@2026! | 全部功能（实际环境密码以管理员交付为准） |
| operator | 操作员 | Operator@2026! | 日常质检业务操作 |
| viewer | 只读 | Viewer@2026! | 仅查看数据 |

> 示例环境的 admin 密码已由管理员修改，如遗忘可由部署人员在服务器使用密码重置工具恢复。

右上角可切换界面语言，登录页即可选择，切换后持久生效。

### 2.2 整体布局

登录后页面分为三部分：

- **左侧导航栏**：11 个功能菜单（仪表盘、规则管理、NASR集群、通话记录、质检命中、CPD记录、号码状态、VOS对接、用户管理、系统配置、实时监控）。
- **顶部栏**：折叠菜单按钮、深色模式开关、语言切换、当前用户信息（头像缩写 + 用户名 + 角色标签）。
- **主内容区**：各功能页面。

点击右上角用户区域可「修改密码」或「退出登录」。

> 注意：修改密码请使用「系统配置」页面内的修改密码表单（需输入原密码）；右上角下拉中的快捷"修改密码"当前版本存在缺陷，不能成功提交（详见第 7 章）。

## 3. 功能使用说明

### 3.1 仪表盘

进入系统后的默认首页，用于掌握当天整体质检情况，数据每 **30 秒**自动刷新。

![仪表盘](images/dashboard.png)

**统计卡片（共 8 个）：**

| 卡片 | 含义 |
| --- | --- |
| 当前活跃通话（30分钟内） | 近 30 分钟内仍处于通话中的通话数 |
| 今日总通话 | 当天新增通话总数 |
| 今日挂机数 | 当天已挂机（挂机原因非空）的通话数 |
| 质检命中数 | 当天规则命中总次数，副文本显示涉及的通话数 |
| 今日ASR请求 | 当天发往 NASR 的识别请求数 |
| ASR成功率 | 有效返回识别结果的请求占比；当天无请求时显示 100% |
| 运行时间 | 当前页面已打开的时长 |
| 启用规则 | 当前处于启用状态的规则数量 |

**今日质检规则命中统计**表：按规则展示"命中次数"和"涉及通话数"，两列均可点击排序，用于快速判断哪些规则最常被触发。

### 3.2 规则管理

规则是平台的核心配置。路径：左侧菜单「规则管理」。

![规则管理列表](images/rules-list.png)

#### 3.2.1 查询规则

顶部筛选区支持：

- **规则名称**：输入名称关键字；
- **规则类型**：关键词 / 正则；
- **状态**：启用 / 禁用；
- **坐席侧**：全部 / 坐席侧 / 客户侧。

点击「搜索」按条件过滤，「重置」清空条件。列表列依次为：ID、规则名称、类型、坐席侧、匹配内容、动作、优先级、企微推送、启用、创建时间、操作。

- 「启用」列是开关，可直接点击启用/停用该规则，变更立即生效（规则引擎也会每 60 秒自动重载一次）。
- 「操作」列提供「编辑」「删除」，删除前会弹出"确定删除该规则？"二次确认。
- 每页默认 20 条，可切换 10/20/50/100 条每页。

#### 3.2.2 新增 / 编辑规则

点击「新增规则」，或在某行点「编辑」，弹出规则表单：

![编辑规则](images/rule-edit.png)

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 必填，最长 60 字，建议见名知意，如"票务诈骗""辱骂检测" |
| 规则类型 | **关键词匹配**：多个词用竖线 `|` 分隔，包含即命中（不区分大小写）；**正则表达式**：按标准正则匹配 |
| 匹配内容 | 关键词示例：`退票|改签|退款|支付宝`；正则示例：`(?:报警|报案|打110)` |
| 坐席侧 | 全部（两侧都匹配）/ 坐席侧（仅本方）/ 客户侧（仅对方） |
| 触发动作 | 记录、告警、挂机、警告、通知、阻断六选一（含义见 3.2.3） |
| 优先级 | 数字 0–999，**值越小优先级越高**，默认 10 |
| 企微推送 | 开关；开启后该规则命中时推送企业微信群消息 |
| 启用规则 | 开关；停用的规则不参与匹配 |
| 描述 | 选填，备注该规则用途 |

填写后点击「保存」，规则立即下发到规则引擎。

#### 3.2.3 六种动作的实际效果（重要）

| 动作 | 标签 | 实际效果 |
| --- | --- | --- |
| 记录 (log) | 记录 | 仅写入"质检命中"记录，用于事后统计 |
| 告警 (alert) | 告警 | 写命中记录（告警类标识），配合企微推送时产生通知 |
| 警告 (warn) | 警告 | 写命中记录（警告类标识），配合企微推送时产生通知 |
| 通知 (notify) | 通知 | 写命中记录，配合企微推送时产生通知 |
| 阻断 (block) | 阻断 | 写命中记录（当前版本不直接执行通信链路阻断） |
| 挂机 (hangup) | 挂断 | **唯一具有实时联动效果的动作**：命中后通知前台对该通话执行挂机，挂机来源记为"质检命中" |

> 使用建议：
> - 只想统计观察 → 用「记录」；
> - 需要班组长/管理层即时知晓 → 用「告警/警告/通知」并开启企微推送；
> - 确认高危、必须当场拦截的场景（如诈骗剧本命中）→ 用「挂机」。
> - 同一通通话、同一侧、同一条规则只命中一次，避免重复触发与刷屏。

#### 3.2.4 配置建议

- 正则规则上线前请先自行验证表达式；非法表达式会被引擎跳过（不影响其他规则）。
- 优先级按风险排序：高危拦截规则给小数字（如 1），普通统计规则给大数字（如 100）。
- 匹配内容避免过于宽泛（如单个"喂""你好"），否则会大量误命中。

### 3.3 NASR 集群

配置 ASR 语音识别后端实例。路径：「NASR集群」。

![NASR集群](images/nasr.png)

列表字段：名称、地址、最大并发、当前任务、权重、平均延迟、状态（启用开关）、更新时间、操作（编辑/删除）。

点击「新增集群」填写：

| 字段 | 说明 |
| --- | --- |
| 名称 | 实例名称，如 `nasr-local-1` |
| 地址 | ASR 服务地址。**请直接填写完整的 `IP:端口` 形式**，如 `127.0.0.1:8089` |
| 端口 | 表单中的端口项（当前版本后端未单独使用，端口请写进地址里） |
| 最大并发 | 该实例允许的最大识别并发，默认 10 |
| 权重 | 多实例负载分担权重，默认 1 |
| 启用 | 是否参与调度 |
| 描述 | 选填 |

系统每 **30 秒**对每个启用实例做一次健康探测（`GET /health`，3 秒超时），实例列表每 60 秒重新加载。健康状态（健康/异常/未知）与平均延迟可在「实时监控」页查看。

### 3.4 通话记录

全部质检通话的统一入口。路径：「通话记录」。

![通话记录](images/calls.png)

**状态页签（点击即筛选）：**

- 全部通话 / 当前通话（通话中，绿色）/ 已挂机（红色）/ 已完成（蓝色）/ 超时（灰色）

**筛选条件：** 通话ID、主叫号码、被叫号码、状态、时间范围、最短时长（秒）、对话轮次（最小~最大）。点击「搜索」执行查询，「重置」恢复默认（默认查**当天**），「导出」可导出 CSV。

列表字段：通话ID、主叫号码、被叫号码、状态、通话时长、ASR轮次、挂机来源、开始时间、结束时间（通话中显示绿色"通话中"标签）、操作。

#### 3.4.1 通话详情（复盘核心页面）

点击某行「详情」，弹出"通话详情"窗口，分三部分：

1. **通话信息**：通话 ID、主叫、被叫、通话时长、开始/结束时间、挂机来源（CPD检测/质检命中/超时/手动/CDR）、挂机原因。
   - **完整录音播放器**：若该通话有 CDR 推送的录音文件（`recording_path` 非空且文件存在），通话信息区下方提供**带进度条的完整录音播放器**，支持播放/暂停/拖动进度。
   - **安全说明**：录音流式接口仅允许访问 `config.yaml` 中 `recording.allowed_dirs` 白名单内的文件；若未显式配置白名单，系统会自动读取上级目录 `nip.conf` 的 `[paths].recording_path` 和 `[vad].vad_record_path` 作为白名单。CDR 推送了白名单外路径的录音将无法播放。
2. **ASR 转写**：聊天气泡形式逐轮展示双方对话——本端（坐席侧）蓝底靠左，远端（客户侧）绿底靠右，每轮带序号和时间。
   - **VAD 分段内联播放器**：若对应轮次有 VAD 切分的音频片段，转写气泡右侧会出现一个**mini 内联播放器**，点击即可直接播放该轮语音，无需打开完整录音。
3. **质检命中**：列出该通话命中的每条规则，显示规则名、动作标签、通话侧、命中的原文片段。

通话仍在进行时，详情窗口每 **3 秒**自动刷新，转写和命中实时追加；通话结束后停止刷新。关闭窗口会自动暂停录音。

> 若转写区显示"暂无转写记录（可能 NASR 服务未启动）"，表示该通话没有产生识别结果，请检查 NASR 集群配置、门控状态和 ASR 成功率（见 3.10）。

> 若通话信息区没有完整录音播放器、或 VAD 分段气泡没有 mini 播放器：前者表示 CDR 未推送录音文件（仅实时 VAD 分段可用），后者表示该轮没有音频切片（可能音频过小被跳过，详见 `core.min_audio_bytes` 配置）。

### 3.5 质检命中

所有规则命中记录的明细。路径：「质检命中」。

![质检命中](images/qc-hits.png)

**筛选条件：** 通话ID、规则名称（下拉可搜索，仅列启用规则）、动作、通话侧、时间范围。「导出」可导出命中明细 CSV（默认同样只查当天，请注意先调整时间范围）。

列表字段：通话ID、规则名称、规则类型、动作、通话侧、主叫、被叫、匹配文本、命中时间、操作。

点击「查看详情」弹出命中详情，包含：

- **命中信息**：通话 ID、规则名称/类型、动作、通话侧、主被叫、命中时间；
- **匹配文本**：本次命中的原文片段（黄底高亮）；
- **完整转写文本**：该侧累积全文，并把第一处匹配文字高亮显示，方便对照上下文研判是否误命中。

### 3.6 CPD 记录

展示前端 CPD 检测（空号/停机/回铃等号码状态）上报的事件。路径：「CPD记录」。

![CPD记录](images/cpd-records.png)

顶部为统计卡片：**今日 CPD 事件总数**、**今日挂机类事件**，以及近 60 天出现次数最多的若干检测类型卡片。

**筛选条件：** 时间范围、通话ID（精确）、类型（可多选，选项后括号内为近 60 天该类型计数）、主叫（模糊）、被叫（模糊）。支持「导出」（GB18030 编码 CSV，可用 Excel 直接打开）。

列表字段：时间、通话ID、类型、主叫、被叫、事件、评分（得分/满分）、命中率、相似度、描述、操作。

### 3.11 VOS 对接

与 VOS（语音运营系统）的对接配置页面，供运营商线路场景下推送质检结果到对端系统使用。路径：「VOS对接」。

![VOS对接](images/vos.png)

> 注意：此功能需 v2.3 及以上版本二进制支持。v2.2 及更早版本无此菜单。

#### 3.11.1 配置项说明

所有 VOS 配置复用后端 `system_config` 表，key 统一加 `vos_` 前缀隔离，与其他系统参数互不干扰。配置项如下：

| 配置项 | 界面字段 | 含义 |
| --- | --- | --- |
| `vos_enabled` | 启用对接 | 总开关，关闭时后端不执行任何 VOS 推送逻辑 |
| `vos_api_url` | VOS 接口地址 | 对端 VOS 系统的 HTTP 接口基地址，如 `http://vos.example.com:8080/api` |
| `vos_local_ip` | 本机 IP | QaManager 所在机器的对外可达 IP，部分 VOS 回调场景需要此值 |

页面顶部自动展示**回调地址**（只读）：`http://<当前域名>:19091/vos`，可一键复制。此地址用于对端 VOS 系统主动回调本平台时的入口，无需手动填写。

#### 3.11.2 操作步骤

1. 左侧菜单进入「VOS对接」（仅 superadmin / admin 可见，见第 5 章）。
2. 填写「VOS 接口地址」和「本机 IP」，打开「启用对接」开关。
3. 点击「测试连通性」：系统向填写的接口地址发一条 HTTP GET，就地显示可达/不可达。
4. 点击页面底部「保存配置」生效。
5. 点击回调地址旁「复制」按钮，将本平台回调地址提供给 VOS 对接方。

#### 3.11.3 对接流程说明

完整对接涉及多方配置，QaManager 侧仅需完成本页面配置即可。对端（nip、nip_mgr、VOS Web）需配合：

```
VOS Web 系统（Tomcat 默认端口 8080）
    │
    ├─ server.conf 配置 SIP/线路参数
    │
    ├─ 回调地址填写 QaManager 回调地址  ← 从本页面获取
    │
    ▼
nip_mgr（SIP 适配器 + CPD/空号推送）
    │
    ├─ config.ini 配置 VOS 推送开关
    │
    ▼
nip（语音抓包 + VAD 切分）
    │
    ├─ nip.conf 中 [paths] recording_path / [vad] vad_record_path
    │
    ▼
QaManager（本平台）
    ├─ 实时接收 VAD 分段 → ASR → 质检匹配
    └─ 命中后按 VOS 接口契约推送到对端
```

> 详细对接参数请参考部署文档。`vos_enabled` 关闭时，VOS 推送逻辑完全旁路，不影响质检主流程。

## 4. 典型操作场景

### 场景一：新增一条"高危关键词实时挂断"规则

1. 「规则管理」→「新增规则」。
2. 规则名称填"票务诈骗-挂断"；类型选**关键词匹配**；匹配内容填 `退票|改签|退机票|退款|退钱|支付宝`。
3. 坐席侧选**客户侧**（诈骗话术通常来自客户）；触发动作选**挂机 (hangup)**；优先级填 `1`。
4. 需要管理层即时知晓时打开**企微推送**；确认"启用规则"为开。
5. 保存。用测试通话念出关键词验证：通话应被实时挂断，且在「质检命中」中产生一条记录。
6. 观察期内若担心误杀，可先把动作改为「告警」运行几天，核对命中质量后再改为「挂机」。

### 场景二：复盘一通被挂断的通话

1. 「通话记录」→ 输入通话 ID（或主叫/被叫号码+时间范围）→「搜索」。
2. 点「详情」：先看"挂机来源/挂机原因"是否为质检命中及具体规则。
3. 在"ASR 转写"区回看双方对话原文；有录音时播放录音核对。
4. 在"质检命中"区查看命中的规则与片段；需要更多上下文可点该命中跳到「质检命中」详情查看完整转写高亮。

### 场景三：导出日报 / 月报

1. 进入对应页面（通话记录、质检命中、CPD记录、号码状态均支持导出）。
2. **先设置好筛选条件与时间范围再点导出**——导出内容严格对应当前筛选条件（通话/命中默认仅当天）。
3. 浏览器下载 CSV：通话记录、质检命中为 UTF-8 编码；CPD 记录、号码状态为 GB18030 编码（Excel 直接打开不乱码）。
4. 单次导出有上限保护（明细类 1 万行，CPD/号码类 100 万行），数据量大时请缩小时间范围分批导出。

### 场景四：配置企业微信群告警

1. 在企业微信群里添加"机器人"，复制其 Webhook 地址。
2. 「系统配置」→ 企业微信通知：打开"启用通知"，粘贴 Webhook，必要时填写 @成员。
3. 页面底部「保存配置」→ 点「测试发送」，群里收到标题为"RT-QC 质检系统测试消息"即配置成功。
4. 回到「规则管理」，把需要告警的规则"企微推送"开关打开即完成。

### 场景五：排查"有通话但没有质检结果"

按以下顺序检查：

1. 「实时监控」→ 服务门控是否为"正常"。若为欠费暂停/离线宽限耗尽，实时质检会被跳过。
2. NASR 是否健康：健康实例数是否为 0、实例是否"异常"、ASR 成功率是否偏低；检查 ASR 实例地址与服务状态。
3. 通话详情中转写区是否为"暂无转写记录"——若是，问题在 ASR 链路（VAD/NASR），不在规则。
4. 有转写但无命中：检查规则是否**启用**、坐席侧是否选对、关键词/正则是否正确、转写置信度是否低于 `asr_confidence_threshold`（默认 0.6，低于阈值的文本不参与匹配）。
5. 命中了但没收到企微消息：检查系统配置里通知总开关、Webhook、以及该规则自身的"企微推送"开关。

## 7. 使用注意事项与常见问题

**Q1：登录提示"验证码错误或已过期"？**
验证码一次性有效且约 5 分钟过期，请点击验证码图片换一张后重新输入。连续输错密码 5 次账号会锁定 30 分钟。

**Q2：右上角用户菜单里的"修改密码"提交报错？**
当前版本该快捷入口缺少原密码校验，无法成功。请在「系统配置 → 修改密码」卡片中凭原密码修改。

**Q3：通话记录/质检命中列表是空的？**
列表默认只查询**当天**数据。请调整时间范围后重新搜索；导出前同样要先改时间范围。

**Q4：规则配了"阻断(block)"为什么通话没被拦？**
当前版本六种动作中只有**挂机(hangup)**会触发实际的实时挂机联动，其余动作以记录、告警通知为主。需要实时拦截请选用"挂机"。

**Q5：NASR 集群页地址显示成 `IP:端口:` 或状态开关异常？**
当前版本集群地址请统一填写为完整的 `IP:端口`（如 `127.0.0.1:8089`），不要把端口单独填在端口框。集群实际健康状况以「实时监控」页探测结果为准。

**Q6：配置了规则但通话一直不命中？**
依次确认：规则"启用"开关已打开 → 坐席侧选择正确 → NASR 集群健康、通话详情中存在转写文本 → 转写置信度不低于系统参数 `asr_confidence_threshold`（默认 0.6）→ 监控页服务门控为"正常"。

**Q7：企业微信收不到通知？**
确认三处开关/配置：系统配置中"启用通知"已开且 Webhook 正确（先点"测试发送"验证）；对应规则的"企微推送"已打开；网络可以访问企业微信接口。消息有聚合去重（同一主叫→被叫组合 3 秒内合并）和限流（约 20 条/分钟）。

**Q8：监控显示"控制中心不可达，余额未知"？**
表示平台暂时连不上授权控制中心，此时**不会按欠费处理**，请检查服务器到控制中心的网络；该状态长期不恢复会进入离线宽限倒计时，宽限耗尽后门控转为暂停状态。

**Q9：页面语言可以切换吗？**
可以。登录页右上角或登录后顶栏右上角均可切换中/英/日/韩/西/葡六种语言，选择后即时生效并保存在浏览器中。

**Q10：账号权限不符合预期（看不到菜单或打开页面提示无权限）？**
菜单显示与数据权限均按角色控制：用户管理、系统配置仅超级管理员可用。请使用超级管理员账号执行管理操作，或联系超级管理员调整角色。

| completed | 已完成 | 蓝色 |
| timeout | 超时 | 灰色 |

挂机来源：`cpd` CPD检测、`asr_qc` 质检命中、`timeout` 超时、`manual` 手动、`cdr` CDR。

### 8.2 规则相关枚举

- 规则类型：`keyword` 关键词、`regex` 正则。
- 坐席侧：`all` 全部、`aleg` 坐席侧、`bleg` 客户侧（系统内部另含 offer_local 本端/answer_remote 远端两类腿标识）。
- 动作：`log` 记录、`alert` 告警、`hangup` 挂断、`warn` 警告、`notify` 通知、`block` 阻断。
- 动作颜色：挂断/阻断-红，告警/警告-橙黄，通知-蓝，记录-灰。

### 8.3 用户角色

`superadmin` 超级管理员、`admin` 管理员、`operator` 操作员、`viewer` 只读；账号状态：1 启用、0 禁用。

### 8.4 门控状态

`normal` 正常、`retained` 欠费暂停实时质检、`offline_expired` 离线宽限耗尽、`starting` 启动中。
