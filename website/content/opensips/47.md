# 一、OpenSIPS脚本语法(机翻,时间有限，机翻为主）


		<a href="47.html"><h1>一、OpenSIPS脚本语法(机翻,时间有限，机翻为主）</h1></a>
                <br/><b>                <ol>
<li>脚本格式</li>
</ol>
<p>OpenSIP 配置脚本有三个主要逻辑部分：</p>
<p>全局参数</p>
<p>模块部分</p>
<p>路由逻辑</p>
<p>1.1 全局参数</p>
<p>通常，在第一部分，您声明OpenSIPS全局参数 - 这些全局或核心参数会影响OpenSIPS核心和可能的模块。</p>
<p>配置网络侦听器、可用的传输协议、分叉（和进程数）、日志记录和其他全局内容由这些全局参数提供。</p>
<p>例：</p>
<p><code>bash
disable_tcp = yes
listen = udp:192.168.3.40:5060
listen = udp:192.168.3.40:5070
fork = yes
children = 4
log_stderror = no</code></p>
<p>1.2 模块部分</p>
<p>对于 OpenSIPS 模块，要加载的模块（默认情况下不加载任何模块）是使用指令 loadmodule 指定的。模块应按名称和可选路径（指向 .so 文件）指定。如果没有提供路径（并且只是模块的名称），则将假定默认路径来定位加载模块（默认路径是 /<em>usr/lib/opensips/modules，</em>如果不是在编译时配置的其他路径。对于配置不同的路径，可以使用模块名称直接推送路径（以获得每个模块的控制），也可以通过 mpath 全局参数全局配置路径（对于所有模块）。</p>
<p>加载模块后，可以使用modparam指令设置模块的参数 - 要列出每个模块的可用参数，参数值的类型（整数或字符串）可以在模块的文档“参数”部分中找到。</p>
<p>例子：</p>
<p><code>bash
    loadmodule &#34;modules/mi_datagram/mi_datagram.so&#34;
    modparam(&#34;mi_datagram&#34;, &#34;socket_name&#34;, &#34;udp:127.0.0.1:4343&#34;)
    modparam(&#34;mi_datagram&#34;, &#34;children_count&#34;, 3)</code>
或</p>
<p><code>bash
mpath=&#34;/usr/local/opensips_proxy/lib/modules&#34;
loadmodule &#34;mi_datagram.so&#34;
modparam(&#34;mi_datagram&#34;, &#34;socket_name&#34;, &#34;udp:127.0.0.1:4343&#34;)
modparam(&#34;mi_datagram&#34;, &#34;children_count&#34;, 3)
loadmodule &#34;mi_fifo.so&#34;
modparam(&#34;mi_fifo&#34;, &#34;fifo_name&#34;, &#34;/tmp/opensips_fifo&#34;)</code></p>
<p>1.3 路由逻辑</p>
<p>路由逻辑实际上是包含用于路由 SIP 流量的 OpenSIPS 逻辑的路由（脚本路由）的总和。与 SIP 流量相关的 OpenSIPS 行为描述是通过此路由完成的。</p>
<p>有不同类型的路线：</p>
<p>顶级路由 - 当某些事件发生时由 OpenSIP 直接触发的路由（如收到 SIP 请求、收到 SIP 回复、事务失败等）</p>
<p>子路由 - 从脚本中的其他路由触发/使用的路由。</p>
<p>路由类型部分中记录了现有的顶级路由、触发时间、处理的 SIP 消息类型、允许的 SIP 操作以及其他操作。</p>
<p>子路由具有名称，并且将通过其名称从脚本中的任何其他路由（top 或 sub）调用它们。子路由可以采用参数（调用时）或返回数字代码（避免返回 0 值，因为这将终止整个脚本。子路由类似于任何编程语言中的函数/过程。请参阅路由指令的说明。</p>
<ol>
<li>数据类型</li>
</ol>
<p>OpenSIPS 脚本语言支持以下数据类型：</p>
<p>基本</p>
<p>整数（32 位，有符号）。</p>
<p>最大值：+2，147，483，647 == 2 ^ 31 - 1</p>
<p>最小值：-2，147，483，648 == - 2 ^ 31</p>
<p>字符串（大小不限）</p>
<p>请注意，某些使用字符串的函数可能具有内部缓冲区，这些缓冲区限制了字符串的最大大小（例如，xlog（） 函数的输出缓冲区可通过xlog_buf_size)</p>
<p>浮点型（打包为字符串），通过 Mathops 模块</p>
<p>复杂</p>
<p>通过<em>$avp变量</em>**列出</p>
<p>通过<em>$json和$xml</em>变量进行映射</p>
<ol>
<li>函数调用约定</li>
</ol>
<p>所有 OpenSIPS 核心和模块函数在内部共享相同的函数接口，因此它们受益于以下调用约定：</p>
<p>任何整数或字符串函数参数也可以使用“持有者”变量传递</p>
<pre><code>ds_select_dst(1, 1);
</code></pre>
<p>...相当于：</p>
<pre><code>$var(x) = 1; ds_select_dst($var(x), $var(x));
</code></pre>
<p>任何字符串函数参数都可以作为格式字符串传递</p>
<pre><code>set_dlg_profile(&#34;caller&#34;, &#34;var(country_code)_var(area)_$fU&#34;);
</code></pre>
<p>文本“$”字符可以使用<strong>“$$”</strong>转义序列包含在格式字符串中</p>
<p>注意：由于性能优化，在字符串参数的情况下，上述约定仍然存在一些例外，因为某些函数仍然要求某些参数是纯静态字符串（例如 save（“location”））。这种情况将在函数的文档中注明。</p>
<p>传递给函数的输入或输出变量不得用引号括起来：</p>
<pre><code>ds_count(1, &#34;a&#34;, $var(out_result));
</code></pre>
<p>整数不再需要作为双引号字符串传递：</p>
<pre><code>ds_select_dst(&#34;1&#34;, &#34;1&#34;);
