参与贡献

从第一个 Pull Request 开始

欢迎修复文档、补充测试、优化信令路径，或实现新的编解码与路由策略。提交前请确认本地构建与测试通过。

  • 运行 ./configure && make -j$(nproc) 与 make check
  • 解析器 / 传输层改动跑 make asan check 与 make tsan check
  • 遵循现有 C 风格：4 空格缩进、snake_case、公共 API 写 Doxygen 注释
  • 新模块需声明 NSBC_MOD()；被信令核心直接调用的加入 HARD_STATIC
  • 大功能先开 Issue，一个 PR 只做一件事
# 典型贡献流程
git clone https://github.com/nwaycn/nsbc.git
cd nsbc
git checkout -b feat/my-change

./configure
make -j$(nproc)
make check

# 解析器 / 传输层改动
make SANITIZE=asan -j$(nproc)
make SANITIZE=tsan -j$(nproc)

git commit -am "feat: 描述你的改动"
git push origin feat/my-change

Contributing

Start with your first pull request

Documentation fixes, test additions, improved signaling paths, new codecs or routing strategies — all welcome. Please make sure local build and tests pass before submitting.

  • Run ./configure && make -j$(nproc) and make check
  • For parser / transport-layer changes also run make asan check and make tsan check
  • Follow existing C style: 4-space indent, snake_case, Doxygen comments on public APIs
  • New modules must declare NSBC_MOD(); those called directly by the signaling core go in HARD_STATIC
  • Open an issue for large features; one PR does one thing
# Typical contribution flow
git clone https://github.com/nwaycn/nsbc.git
cd nsbc
git checkout -b feat/my-change

./configure
make -j$(nproc)
make check

# For parser / transport-layer changes
make SANITIZE=asan -j$(nproc)
make SANITIZE=tsan -j$(nproc)

git commit -am "feat: describe your change"
git push origin feat/my-change
Developer resources

Runnable event-subscription examples

examples/event_client/ provides clients in four languages that connect over UDS and print call events in real time.

C event_client.cgcc event_client.c -o event_client → GO main.gocd go && go run main.go →
PY event_client.pypython3 event_client.py → RS src/main.rscd rust && cargo run →

All clients subscribe to SESSION_CREATE, SESSION_ANSWER, SESSION_END. See src/include/event_bus.h for the event format.

Code of conduct

Be professional and respectful

Technical discussions can get heated — but always attack the problem, never the person. Personal attacks, discriminatory speech, or harassment will not be tolerated.

We encourage

  • Reproducible steps and log snippets
  • Searching existing issues before asking
  • Specific feedback on other people's proposals
  • Tests, documentation and config samples

We don't accept

  • Sharing other people's privacy or credentials
  • Off-topic promotion content
  • Repeated low-quality duplicate issues
  • Undisclosed security vulnerabilities discussed publicly

Have an idea but not sure where to start?

Describe your scenario and reproduction steps in an issue — we'll help figure out whether it belongs on the roadmap.
