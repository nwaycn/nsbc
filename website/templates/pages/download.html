从源码构建

四步跑通第一个呼叫

1. 安装依赖（Debian / Ubuntu）

sudo apt-get update
sudo apt-get install -y build-essential pkg-config git \
  libssl-dev libsrtp2-dev libpcre2-dev libedit-dev \
  libsqlite3-dev libcurl4-openssl-dev libopus-dev

# Rust 工具链，仅 Web 边车需要
curl --proto '=https' --tlsv1.2 -sSf \
  https://sh.rustup.rs | sh
source $HOME/.cargo/env

2. 构建核心

git clone https://github.com/nwaycn/nsbc.git
cd nsbc
chmod +x configure

# 扫描 src/，读取 conf/modules.conf
./configure
make -j$(nproc)
make check          # 单元测试

3. 构建 Web 边车

cd web

# 国内网络建议配置 crates 镜像后执行
make vendor
make build-acme
# 自动复制 nsbc-web 与 static/ 到上级目录
cd ..

4. 启动

# 先启动边车：生成 SQLite 与自签 TLS 证书
nohup ./nsbc-web &
sleep 3

# 再启动 C 守护进程
nohup ./nsbcd -c conf/nsbc.yaml &

# 浏览器验证
https://<your-ip>/webrtc.html
默认测试账号：分机 1000 – 1019，密码 876876， Realm nsbc.local。两个已注册分机（如 1001 与 1002）即可直接互拨。 管理台默认账号 admin / Admin123，首次登录后请立即修改。
排障开关：registrar.force_register_ok: 1 会跳过 REGISTER 的 Digest 与安全围栏检查， 仅用于内网联调；生产环境务必改为 0，并在 Web 控制台为分机设置密码。

TLS 证书

三种证书来源，按优先级自动选择

  • 预置证书 — 指向自己的 cert_path / key_path
  • 自签名 — auto_generate: true，内网默认，每小时轮换
  • ACME — public: true + 域名，自动签发 Let's Encrypt

SIP TLS 与 Web HTTPS 共享同一套证书文件；nsbcd 只读取，不参与续期。

# 方式一：acme.sh 独立模式签发
acme.sh --issue -d nsbc.nway.com.cn \
  --server https://acme-v02.api.letsencrypt.org/directory \
  --standalone

# 方式二：部署到部署根目录 tls/
acme.sh --install-cert -d nsbc.nway.com.cn \
  --key-file       ../tls/key.pem \
  --fullchain-file ../tls/cert.pem

# 方式三：内网自签名（默认）
# conf/nsbc.yaml
web:
  tls:
    auto_generate: true
    validity_days: 2

Build from source

Your first call in four steps

1. Install dependencies (Debian / Ubuntu)

sudo apt-get update
sudo apt-get install -y build-essential pkg-config git \
  libssl-dev libsrtp2-dev libpcre2-dev libedit-dev \
  libsqlite3-dev libcurl4-openssl-dev libopus-dev

# Rust toolchain, only needed for the web sidecar
curl --proto '=https' --tlsv1.2 -sSf \
  https://sh.rustup.rs | sh
source $HOME/.cargo/env

2. Build the core

git clone https://github.com/nwaycn/nsbc.git
cd nsbc
chmod +x configure

# Scans src/, reads conf/modules.conf
./configure
make -j$(nproc)
make check          # unit tests

3. Build the web sidecar

cd web

# On slow networks, configure a crates mirror first
make vendor
make build-acme
# Copies nsbc-web and static/ into the parent directory
cd ..

4. Start

# Start the sidecar first: generates SQLite and self-signed TLS cert
nohup ./nsbc-web &
sleep 3

# Then start the C daemon
nohup ./nsbcd -c conf/nsbc.yaml &

# Verify from a browser
https://<your-ip>/webrtc.html
Default test accounts: Extensions 1000 – 1019, password 876876, Realm nsbc.local. Two registered extensions (e.g. 1001 and 1002) can call each other immediately. Admin console default account is admin / Admin123 — change it right after first login.
Debug switch: registrar.force_register_ok: 1 skips Digest and security fence checks on REGISTER. Use only for intranet integration testing. In production, set it to 0 and set passwords for extensions in the web console.

TLS certificates

Three certificate sources, picked automatically by priority

  • Pre-supplied — point to your own cert_path / key_path
  • Self-signed — auto_generate: true, default for intranet, rotated hourly
  • ACME — public: true + domain, auto-issued via Let's Encrypt

SIP TLS and web HTTPS share the same certificate files. nsbcd only reads them — it does not participate in renewal.

# Method 1: acme.sh standalone issuance
acme.sh --issue -d nsbc.nway.com.cn \
  --server https://acme-v02.api.letsencrypt.org/directory \
  --standalone

# Method 2: deploy into the deployment root tls/
acme.sh --install-cert -d nsbc.nway.com.cn \
  --key-file       ../tls/key.pem \
  --fullchain-file ../tls/cert.pem

# Method 3: self-signed for intranet (default)
# conf/nsbc.yaml
web:
  tls:
    auto_generate: true
    validity_days: 2
