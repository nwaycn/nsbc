功能特性

NSBC 把会话边界所需的能力拆成清晰的功能面：信令、媒体、安全、PBX 与可观测性。你可以只用其中一部分，也可以全部启用。

自研 C11 SIP 协议栈

不基于 PJSIP、Sofia-SIP、reSIProcate。每个解析器、事务状态机与 B2BUA 环路都从零实现，可审计、可预测。

  • RFC 3261 / 3262 / 3264 / 3265
  • Digest MD5 鉴权，支持 qop=auth
  • 事务定时器（T1 / T2 / T4 / Timer D）可配置
  • SIP over WebSocket：RFC 7118，子协议 sip

真 B2BUA 与拓扑隐藏

每通呼叫都在 NSBC 终止并重新发起，A / B 腿拥有独立事务与对话，内部地址不会泄漏给对端。

  • R-URI / Contact / Via / Record-Route 改写
  • RFC 7989 Session-ID 贯通
  • DoS 防护与欺诈检测内置信令层
  • 会话定时器与挂断原因规范化

媒体锚定与 DTLS-SRTP

OpenSSL 驱动 DTLS-SRTP 密钥协商，libsrtp2 完成媒体加密；WebRTC 与 SIP 终端之间可自动选择中继。

  • SRTP / RTP 双向中继，rtcp-mux 支持
  • Jitter Buffer、VAD、DTMF（RFC 2833 / INFO）
  • T.38 Fax 透传与媒体 FEC
  • Media Bug 被动旁路，用于监听与质检

PBX 与呼叫中心

拨号计划、IVR、语音信箱、Ring Group、会议、ACD 队列与坐席池全部内置，与 SBC 共享一套配置。

  • YAML 紧凑规则 + Web 结构化动作编排
  • 坐席池、技能队列与排队策略
  • 时段路由与主备中继切换
  • IMS PAI / PPID / PCPI 头注入

录音与计费

每通道可独立录音，CDR 采用 WAL 式持久化，可挂接外部计费钩子。

  • WAV / G.729，mixed / separate 模式
  • SIPREC 录音对接
  • WAL 式 CDR，崩溃后可恢复
  • 按 disposition 打标的呼叫统计

WebRTC 就绪

浏览器与移动端通过 SIP over WebSocket 接入，与既有 SIP 终端、运营商中继互通。

  • WSS 监听，Sec-WebSocket-Protocol: sip
  • ICE / STUN / TURN、DTLS 指纹校验
  • BUNDLE、rtcp-mux、ICE 重启
  • 配套 Android / Desktop / iOS SDK

安全与访问控制

从传输层到应用层建立多层防护，降低被扫描、爆破与盗打的概率。

  • SIPS（TLS）与 WSS 加密信令
  • Fail2ban 式自动封禁：认证失败 / 注册 / INVITE 限速
  • GeoIP allowlist / denylist（ipset 数据文件热重载）
  • STIR / SHAKEN 签发与验证（部分实现）

模块系统与可观测性

静态链接 + 动态 mod_*.so 两层模型；运行状态通过指标、日志与事件总线完整暴露。

  • configure 期选择模块，mod.load 决定加载清单
  • Prometheus 指标、JSON 日志与 trace_id
  • HEPv3 抓包：Homer / sngrep / heplify-server
  • 事件总线：会话、注册、封禁、录音、配置变更

Features

NSBC decomposes session-border capabilities into clean functional planes: signaling, media, security, PBX and observability. Use only the slices you need, or enable all of them.

Homegrown C11 SIP Stack

Not built on PJSIP, Sofia-SIP or reSIProcate. Every parser, transaction state machine and B2BUA loop is implemented from scratch — auditable and predictable.

  • RFC 3261 / 3262 / 3264 / 3265
  • Digest MD5 authentication with qop=auth
  • Configurable transaction timers (T1 / T2 / T4 / Timer D)
  • SIP over WebSocket: RFC 7118, subprotocol sip

True B2BUA & Topology Hiding

Every call is terminated and re-originated inside NSBC. A / B legs have independent transactions and dialogs — internal addresses are never leaked to the peer.

  • R-URI / Contact / Via / Record-Route rewriting
  • RFC 7989 Session-ID propagation
  • DoS protection and fraud detection built into the signaling layer
  • Session timer and standardized disconnect causes

Media Anchoring & DTLS-SRTP

OpenSSL drives DTLS-SRTP key negotiation, libsrtp2 handles media encryption. A relay path can be automatically selected between WebRTC and SIP terminals.

  • Bidirectional SRTP / RTP relay with rtcp-mux support
  • Jitter Buffer, VAD, DTMF (RFC 2833 / INFO)
  • T.38 Fax passthrough and media FEC
  • Media Bug passive tap for monitoring and quality inspection

PBX & Call Center

Dial plan, IVR, voicemail, Ring Group, conference, ACD queue and agent pool are all built-in — sharing one config with the SBC.

  • Compact YAML rules + structured web action orchestration
  • Agent pool, skill-based queues and queuing strategies
  • Time-of-day routing and active/standby trunk failover
  • IMS PAI / PPID / PCPI header injection

Recording & Billing

Per-channel independent recording; WAL-style CDR persistence with hooks for external billing systems.

  • WAV / G.729, mixed / separate modes
  • SIPREC recording integration
  • WAL-style CDR, crash-recoverable
  • Disposition-tagged call statistics

WebRTC Ready

Browsers and mobile clients connect via SIP over WebSocket, interoperating with existing SIP endpoints and carrier trunks.

  • WSS listener with Sec-WebSocket-Protocol: sip
  • ICE / STUN / TURN, DTLS fingerprint verification
  • BUNDLE, rtcp-mux, ICE restart
  • Companion Android / Desktop / iOS SDK

Security & Access Control

Multi-layer defense from transport to application — reducing exposure to scanning, brute force and toll fraud.

  • SIPS (TLS) and WSS encrypted signaling
  • Fail2ban-style auto-ban: auth failure / REGISTER / INVITE rate limits
  • GeoIP allowlist / denylist (hot-reloadable ipset data files)
  • STIR / SHAKEN signing and verification (partial implementation)

Modular System & Observability

Two-layer model: static linking + dynamic mod_*.so. Runtime state is fully exposed via metrics, logs and an event bus.

  • Module selection at configure time; mod.load determines load manifest
  • Prometheus metrics, JSON logs with trace_id
  • HEPv3 packet capture: Homer / sngrep / heplify-server
  • Event bus: sessions, registrations, bans, recordings, config changes

Typical Scenarios

Three of the most common deployment patterns

Enterprise Branch

Branch ↔ HQ Interconnection

Branch softphones register with a local NSBC and interconnect with HQ PBX via SIP trunk — only the SBC address is exposed to the public Internet.

  • Internal extension dialing
  • Public NAT traversal
  • Topology hiding and number normalization
Contact Center

Agent Access & Recording

Agents register once; ACD queues distribute calls by skill; media is recorded centrally and written to CDR.

  • Agent pool and skill-based queues
  • Centralized mixed-mode recording
  • Realtime monitoring and quality-inspection tap
Carrier Access

SIP Trunk Border

Between a carrier trunk and your enterprise platform — protocol normalization, number rewriting and active/standby failover to boost call completion rate.

  • Trunk registration and HA
  • Prefix stripping and number rewriting
  • IMS identity header injection
