快速入门

NSBC 由两个进程组成：nsbcd（C11 SIP 守护进程）与 nsbc-web（Rust 管理面边车）。两者共享同一份 conf/nsbc.yaml 与同一套 TLS 证书。

  1. 构建 — 安装依赖后执行 ./configure && make -j$(nproc)，再在 web/ 中构建边车。
  2. 启动边车 — ./nsbc-web 会在首次启动时生成 SQLite 数据库与自签名 TLS 证书。
  3. 启动内核 — ./nsbcd -c conf/nsbc.yaml 读取刚生成的证书并监听 5060 / 5061 / 5062。
  4. 验证 — 浏览器打开 https://<ip>/webrtc.html，用默认分机注册并互拨。
默认账号：分机 1000 – 1019，密码 876876，Realm nsbc.local； 管理台 admin / Admin123（首次登录请修改）。

最小可用配置

# conf/nsbc.yaml —— 相对路径以本文件所在目录为基准
net:
  sip_udp_port: 5060
  sip_tcp_port: 5060
  sip_tls_port: 5061
  tls_enabled: true
  tls_cert: "../tls/cert.pem"
  tls_key:  "../tls/key.pem"

sip:
  bind: "0.0.0.0:5060"
  ws:
    enabled: true
    port: 5062
    tls: true

registrar:
  force_register_ok: 0   # 生产环境必须为 0
  force_expires: 1800
  expires_jitter_s: 100

模块系统

两级模型：主二进制硬依赖的模块静态链接；其余编译为 mod_*.so，启动时按 mod.load 清单加载。

运行时启停

modules:
  # enable 为白名单；与 disable 同时存在时以 enable 为准
  disable:
    - hello
    - asr_tts

mod.load 查找顺序

  1. exe_dir/mod/mod.load
  2. YAML core.mods_load_path
  3. build/mod/mod.load
  4. build/mod.load（兼容遗留）
  5. /etc/nsbc/mod/mod.load

清单中只写裸文件名（例如 mod_codecs.so），dlopen 基目录由 mod.load 所在目录推导。

编写自定义模块

#include "module.h"

static int my_start(nsbc_modmgr_t *m);
static int my_stop(nsbc_modmgr_t *m);
static int my_reload(nsbc_modmgr_t *m);

NSBC_MOD_DEFINE(my_module,
    .version    = "0.5.6-beta",
    .init_level = MOD_L_FINAL,
    .deps       = NULL,
    .start      = my_start,
    .stop       = my_stop,
    .reload     = my_reload,
);

放入 src/mod/my_module/ 后重新执行 ./configure，模块会被自动识别并同时构建为静态与动态形式。

SIP 与媒体

注册与保活

客户端应在 Expires / 2 内刷新注册，并周期性发送 OPTIONS 探测；连续 3 次无响应时应重新注册。服务端可用 force_expires 统一覆盖注册周期，并用 expires_jitter_s 打散刷新时间，避免注册风暴。

WebRTC 接入

浏览器通过 WSS 接入，子协议固定为 sip，路径 /ws。SDP 需包含 ICE、DTLS 指纹、BUNDLE 与 rtcp-mux；NSBC 在 B 腿为 WS/WSS 时会自动选择 SRTP 中继。

编解码策略

m=audio 40000 RTP/SAVPF 111 0 8 9
a=rtpmap:111 opus/48000/2
a=fmtp:111 maxplaybackrate=8000;useinbandfec=1
a=rtpmap:0   PCMU/8000
a=rtpmap:8   PCMA/8000
a=rtpmap:9   G722/8000

m=video 40002 RTP/SAVPF 96
a=rtpmap:96 H264/90000
a=fmtp:96 level-asymmetry-allowed=1;packetization-mode=1;profile-level-id=42e01f

将 H.264 收敛到 Baseline（42e01f）、Opus 限定 maxplaybackrate=8000，可显著提升与老旧终端、PSTN 网关的互通成功率。

媒体模式

  • media.default_mode: relay — 强制媒体锚定，SBC 可见 RTP 统计并支持录音。
  • media.default_mode: bypass — 信令改写后媒体直通；WebRTC 场景会自动忽略。
  • media.trust_private: true — 内网对等呼叫可跳过部分 NAT 改写。

拨号计划

紧凑格式为 被叫模式:优先级:目标，多条规则以竖线分隔；也可在 Web 控制台用结构化动作构建。

dialplan:
  rules: "alice:0:alice|bob:0:bob|^[0-9]+$:0:$0"
动作说明
路由到分机转发到内部分机（如 2001）
路由到中继转发到外部 SIP 中继（如 trunk = ACME-IMS）
路由到组按策略转发到网关组（least_busy）
播放 IVR路由到 IVR 菜单
开始录音mode=mixed、format=wav
号码剥离 / 覆盖去掉前 N 位，或用捕获组替换被叫号码
SIP 头重写设置 From display / URI、R-URI、Contact 参数
IMS 身份头自动构建 PAI / PPID / PCPI

排障

核心无法启动

tail -f logs/nsbcd.log
ss -tulpn | grep 5060          # 端口冲突
ldd ./nsbcd | grep -E "srtp|ssl"  # 依赖缺失

常见原因：5060 被占用、/var/run/nsbc 或 /var/log/nsbc 权限不足、tls_enabled: true 但证书缺失。

REGISTER 未返回 401

若客户端直接收到 200 OK，说明 registrar.force_register_ok 为 1。该开关会跳过 Digest、安全围栏与 HA1 用户存在性检查，仅用于联调；生产环境请设为 0 并在 Web 控制台配置密码。

单通语音 / 媒体未转发

  • 确认 media.default_mode 为 relay（bypass 会完全跳过转发）。
  • 内网对等呼叫将 media.trust_private 设为 true。
  • 确认 RTP 端口段（默认 10000–59999）没有被其他服务占用。
  • 检查 profile 的 external_rtp_ip 是否与公网映射一致。

TLS / WSS 无法工作

# 验证证书与 5062 端口
openssl s_client -connect nsbc.nway.com.cn:5062 -quiet
# 日志应出现 tls 证书路径
grep -i tls logs/nsbcd.log | tail

常见问题

NSBC 需要外部数据库吗？

不需要。C 核心零数据库依赖；只有 Rust 边车 nsbc-web 使用 SQLite（可选 PostgreSQL / MySQL）存储管理面数据。

支持 Windows 或 macOS 吗？

当前仅支持 Linux x86_64（内核 4.15+）。ARM64 与 Raspberry Pi OS 在路线图中。

与 OpenSIPS / FreeSWITCH 是什么关系？

NSBC 的 SIP 栈完全自研，不使用上述项目的代码；模块管理器与配置布局借鉴了 FreeSWITCH 的思路，但已去除冗余。

可以只做媒体中继吗？

可以。关闭不必要的 PBX 应用模块后，NSBC 仍可作为媒体边界与路由节点使用；WebRTC 场景会自动选择 SRTP 中继。

许可证是什么？

Apache License 2.0。内嵌的 3rd/bcg729 保留 LGPL-2.1，3rd/cjson 保留 MIT。

如何获取商业支持？

Quick start

NSBC consists of two processes: nsbcd (C11 SIP daemon) and nsbc-web (Rust management-sidecar). Both share the same conf/nsbc.yaml and the same TLS certificates.

  1. Build — Install dependencies, run ./configure && make -j$(nproc), then build the sidecar inside web/.
  2. Start the sidecar — ./nsbc-web generates the SQLite database and a self-signed TLS cert on first run.
  3. Start the core — ./nsbcd -c conf/nsbc.yaml reads the freshly generated certs and listens on 5060 / 5061 / 5062.
  4. Verify — Open https://<ip>/webrtc.html in a browser, register with a default extension and call another.
Default accounts: Extensions 1000 – 1019, password 876876, Realm nsbc.local; admin console admin / Admin123 (change after first login).

Minimum working config

# conf/nsbc.yaml — relative paths are resolved against the directory of this file
net:
  sip_udp_port: 5060
  sip_tcp_port: 5060
  sip_tls_port: 5061
  tls_enabled: true
  tls_cert: "../tls/cert.pem"
  tls_key:  "../tls/key.pem"

sip:
  bind: "0.0.0.0:5060"
  ws:
    enabled: true
    port: 5062
    tls: true

registrar:
  force_register_ok: 0   # must be 0 in production
  force_expires: 1800
  expires_jitter_s: 100

Module system

Two-tier model: modules that the main binary hard-depends on are statically linked; the rest compile as mod_*.so and are loaded at startup per the mod.load manifest.

Runtime enable/disable

modules:
  # enable is a whitelist; if both enable and disable are present, enable wins
  disable:
    - hello
    - asr_tts

mod.load lookup order

  1. exe_dir/mod/mod.load
  2. YAML core.mods_load_path
  3. build/mod/mod.load
  4. build/mod.load (legacy compatibility)
  5. /etc/nsbc/mod/mod.load

The manifest contains only bare filenames (e.g. mod_codecs.so). The dlopen base directory is derived from where mod.load lives.

Writing a custom module

#include "module.h"

static int my_start(nsbc_modmgr_t *m);
static int my_stop(nsbc_modmgr_t *m);
static int my_reload(nsbc_modmgr_t *m);

NSBC_MOD_DEFINE(my_module,
    .version    = "0.5.6-beta",
    .init_level = MOD_L_FINAL,
    .deps       = NULL,
    .start      = my_start,
    .stop       = my_stop,
    .reload     = my_reload,
);

Drop it into src/mod/my_module/, rerun ./configure, and the module is picked up automatically — built as both static and dynamic.

SIP & media

Registration & keepalive

Clients should refresh registration before Expires / 2, and send periodic OPTIONS probes. Re-register if three consecutive probes go unanswered. The server can uniformly override registration period via force_expires, and jitter refresh times with expires_jitter_s to avoid registration storms.

WebRTC access

Browsers connect over WSS, sub-protocol fixed to sip, path /ws. SDP must include ICE, DTLS fingerprint, BUNDLE and rtcp-mux. NSBC automatically chooses SRTP relay when the B-leg is WS/WSS.

Codec policy

m=audio 40000 RTP/SAVPF 111 0 8 9
a=rtpmap:111 opus/48000/2
a=fmtp:111 maxplaybackrate=8000;useinbandfec=1
a=rtpmap:0   PCMU/8000
a=rtpmap:8   PCMA/8000
a=rtpmap:9   G722/8000

m=video 40002 RTP/SAVPF 96
a=rtpmap:96 H264/90000
a=fmtp:96 level-asymmetry-allowed=1;packetization-mode=1;profile-level-id=42e01f

Constraining H.264 to Baseline (42e01f) and Opus to maxplaybackrate=8000 dramatically improves interoperability with legacy terminals and PSTN gateways.

Media modes

  • media.default_mode: relay — Force media anchoring; the SBC sees RTP stats and can record.
  • media.default_mode: bypass — Signaling rewritten, media passes through; silently ignored in WebRTC scenarios.
  • media.trust_private: true — Skip some NAT rewrites for intranet peer-to-peer calls.

Dialplan

Events

The core publishes structured events on the event bus. Subscribe via ESL or data.sock: SESSION_CREATE, SESSION_ANSWER, SESSION_END, REGISTER_SUCCESS, REGISTER_EXPIRE, BAN_ADD, BAN_REMOVE, RECORDING_START, RECORDING_STOP, CFG_CHANGE.

Management API

nsbc-web exposes a REST interface under /api/v1: call control, extension management, dialplan editing, CDR queries, and config hot reload. Authentication is via JWT (argon2id password hashes stored in the database).

# Paths below depend on your actual deployment

Troubleshooting

Core won't start

tail -f logs/nsbcd.log
ss -tulpn | grep 5060          # port conflict
ldd ./nsbcd | grep -E "srtp|ssl"  # missing dependency

Common causes: 5060 already in use, insufficient permissions on /var/run/nsbc or /var/log/nsbc, tls_enabled: true but no certificates present.

REGISTER doesn't return 401

If clients receive 200 OK directly, registrar.force_register_ok is 1. This flag skips Digest, security fence and HA1 user-existence checks and is for integration testing only. In production, set it to 0 and configure passwords in the web console.

One-way audio / media not relayed

  • Confirm media.default_mode is relay (bypass skips relay entirely).
  • For intranet peer-to-peer calls set media.trust_private to true.
  • Confirm the RTP port range (default 10000–59999) is not in use by another service.
  • Check that the profile's external_rtp_ip matches the public NAT mapping.

TLS / WSS not working

# verify cert and port 5062
openssl s_client -connect nsbc.nway.com.cn:5062 -quiet
# log should mention the tls cert path
grep -i tls logs/nsbcd.log | tail

FAQ

Does NSBC need an external database?

No. The C core has zero database dependency. Only the Rust sidecar nsbc-web uses SQLite (optionally PostgreSQL / MySQL) to store management-plane data.

Is Windows or macOS supported?

Currently only Linux x86_64 (kernel 4.15+). ARM64 and Raspberry Pi OS are on the roadmap.

What's the relationship to OpenSIPS / FreeSWITCH?

NSBC's SIP stack is fully self-developed — it does not use code from those projects. The module manager and config layout draw ideas from FreeSWITCH, but have been streamlined.

Can I use it for media relay only?

Yes. After disabling unnecessary PBX application modules, NSBC still works as a media boundary and routing node. WebRTC scenarios automatically pick SRTP relay.
