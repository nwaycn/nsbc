## 🟡 Medium 级

### R-01: `stub_mods.c` 80+ 处 `snprintf` 返回值未检查

**位置**: `src/core/stub_mods.c` 全文件（~80 处），典型模式：
```c
snprintf(tr->name, sizeof(tr->name), "%s", j->valuestring);
```

**对照**: `signaling.c` 里的 snprintf **已经做了正确检查**：
```c
int n = snprintf(out_ruri, outsz, "sip:%s@%s:%u", dres.dst_number, tr->host, tr->port);
if (n < 0 || (size_t)n >= outsz) return NSBC_NOMEM;
```

**风险分析**:
- 截断概率低（trunk->name/group->name/route->target 这些字段通常 < 64 字节，缓冲区也在 64-256 字节）
- 但格式违规——截断后字符串被静默截断，**没有返回错误给调用方**，导致 trunk 名称被截断成半字符串，后续 SIP URI 构造出错
- `out_err` 缓冲区路径上截断后错误消息不完整，诊断困难

**建议**: 对 `snprintf(out_err, ...)` 路径优先加检查（错误消息截断直接影响运维诊断）。对 trunk/gateway/dialplan 这些短字段路径，如果缓冲区大小 >= 目标字段预期上限 + 16 字节可以暂时容忍，但要在代码注释里标注"已知截断豁免"。

### R-02: DB Pool PostgreSQL/MySQL 未设 `max_connections`

**位置**: `web/src/db/mod.rs:917-925`

```rust
let pool = if backend == "sqlite" {
    PoolOptions::<Any>::new()
        .max_connections(1)   // ✅ SQLite 显式锁定为 1
        .connect(dsn).await?
} else {
    Pool::<Any>::connect(dsn).await?  // ❌ 用 sqlx 默认 10
};
```

**风险分析**:
- sqlx 默认 `max_connections = 10`，`min_connections = 0`
- PostgreSQL 后端：CDR 写入 + 20 个 API 路由并发 + sync 周期推送 + auth 查询，并发高峰时可能等待连接排队
- 不是 crash 级问题——sqlx Pool 会排队等待而非拒绝请求，但延迟会增加
- SQLite 已正确设为 1（避免 WAL 并发竞争），PostgreSQL/MySQL 被遗漏

**建议**: 为 PostgreSQL/MySQL 加可配置的 max_connections，例如读 `NSBC_DB_POOL_MAX` 环境变量，默认值 10（不改变现有行为但让运维可调整）。最小改动：

```rust
let mut builder = PoolOptions::<Any>::new();
if let Ok(v) = std::env::var("NSBC_DB_POOL_MAX") {
    if let Ok(n) = v.parse::<u32>() { builder = builder.max_connections(n); }
}
if backend == "sqlite" { builder = builder.max_connections(1); }
let pool = builder.connect(dsn).await?;
```

## 🔵 Low 级

### R-03: `config.rs` `apply_env_overrides` 无前置格式校验

**位置**: `web/src/config.rs:452-485`

```rust
fn apply_env_overrides(mut cfg: WebConfig) -> WebConfig {
    if let Ok(v) = std::env::var("NSBC_WEB_BIND") {
        cfg.web.bind = v;  // 直接覆盖，无 "ip:port" 格式检查
    }
    // NSBC_JWT_SECRET / NSBC_AUTH_ACCOUNTS / NSBC_DB_DSN / ...
}
```

**实际风险**: **很低**。调用链上有兜底：
- `cfg.web.bind` → 最终经 `bind_addr()` → `.parse::<SocketAddr>()` → 失败返回 `Err(String)` → Web 启动时 fail-fast
- `cfg.db.dsn` → 经 `connect_and_migrate()` → sqlx 解析 dsn 失败会返回 `Err` → DB 降级为 None（不阻塞核心 UDS 通道）
- `cfg.auth.jwt_secret` → 后续 `TokenSvc::new` 会校验 secret 长度

**与 mod.rs detect_public_ip 对比**: `NSBC_PUBLIC_IP` 做了 `is_valid_ipv4()` 显式校验——**两边标准不一致**

**建议**: 不是立即需要改的 bug，但可以统一 env var 校验风格——要么在 apply_env_overrides 内做前置校验，要么把校验逻辑集中到各自的构造函数里（当前分散在多个地方）。
