## 🟡 Medium 级

### R-04: HTTP 服务器（axum + hyper）无显式 timeout

**位置**: `web/src/main.rs:622-627` (axum) + `web/src/main.rs:656-658` (hyper http1)

**证据**:
```rust
// axum HTTP — 无 .tcp_keepalive() 或 .http1() timeout
axum::serve(listener, app.into_make_service_with_connect_info::<SocketAddr>())
    .with_graceful_shutdown(shutdown_signal())
    .await?;

// hyper TLS — 无 .keep_alive() 或 .header_read_timeout()
hyper::server::conn::http1::Builder::new()
    .serve_connection(io, svc)
    .await;
```

**风险分析**:
- **不会 crash**，但可能导致"僵尸连接"：HTTP 客户端连接后不发请求 → TCP 层 keepalive 依赖系统默认（Linux 默认 7200s！）→ 连接一直挂着
- 每个僵尸连接占一个 tokio task（`axum::serve` 默认 `max_concurrent_connections` 无上限）
- 在 Web 管理端这个场景下风险很低（管理员少、连接短），但如果未来 nsbc-web 对外暴露 API 或接入第三方 → 成为 DoS 入口
- 对比 **coreclient.rs:767-818** 有完整 timeout（`NSBC_CORE_TIMEOUT_MS`，默认 5000ms），设计明显更完整

**建议**:
- axum HTTP: 加 `.http1().header_read_timeout(Duration::from_secs(10))` + `.tcp_keepalive(Some(Duration::from_secs(30)))`
- hyper TLS: 加 `.keep_alive(true)` + `.header_read_timeout(Duration::from_secs(10))`
- 最小改动 2-3 行/处

### R-05: SQLx Pool 无 acquire_timeout / idle_timeout / max_lifetime

**位置**: `web/src/db/mod.rs:911-941` (connect_and_migrate)

**当前**:
```rust
let mut builder = PoolOptions::<Any>::new();
// SQLite: max_connections(1)
// PostgreSQL/MySQL: read NSBC_DB_POOL_MAX, default 10
// — 没设 acquire_timeout / idle_timeout / max_lifetime
```

**SQLx 默认值**:
| 参数 | 默认值 | 问题 |
|---|---|---|
| `acquire_timeout` | 30s | 连接池满时 API handler 等 30s 才返回 500 → 体感慢 |
| `idle_timeout` | **永不关闭** | PostgreSQL 服务器有 `idle_in_transaction_session_timeout` 默认 4h，Pool 里的空闲连接被 Postgres 关闭后下次使用报错 "connection reset by peer" |
| `max_lifetime` | **永不回收** | 长时间运行的连接可能被 Postgres `max_connections` 占满 |

**风险等级**: 低。SQLx 内部有自动重连机制，"connection reset by peer" 会自动 acquire 新连接。但 idle_timeout 和 max_lifetime **是推荐的健康调优**。

**建议**:
```rust
builder = builder
    .acquire_timeout(Duration::from_secs(5))       // 连接池满快速失败
    .idle_timeout(Duration::from_secs(300))         // 5 分钟空闲后关闭
    .max_lifetime(Duration::from_secs(3600));       // 1 小时强制回收
```
3 行，放在 `connect_and_migrate` builder 初始化里。

## 🔵 Low 级

### R-06: TLS ServerConfig 自签名 + with_no_client_auth

**位置**: `web/src/tls.rs:191-194`

```rust
let rustls_config = ServerConfig::builder()
    .with_no_client_auth()
    .with_single_cert(cert_chain, key)?;
```

**判定**: **设计合理，但应文档化**。

- nsbc-web 管理端 TLS 目标是加密浏览器 ↔ Web 服务器的流量（防止内网嗅探）
- 自签名证书：ACME 公网不可用时自动 fallback，内网部署合理（浏览器弹窗用户点继续）
- `with_no_client_auth()`：Web 管理端不需要双向认证（admin 密码已保护）

**不建议改**。只需要在 `tls.rs` 头部注释里说明"本 Web 管理端 TLS 用于内网加密传输，不是面向公网 API 网关"。
