## 🟠 High 级

### R-07: HA 心跳包 `(void)sendto` — 返回值被丢弃

**位置**: `src/ha/ha.c:186`

```c
int n = snprintf(pkt, sizeof(pkt), "NSBC-HB/1 %llu %d %d %s\n",
                 (unsigned long long)++seq, ...);
if (h->have_peer)
    (void)sendto(h->fd, pkt, (size_t)n, MSG_NOSIGNAL,
                 (struct sockaddr *)&h->peer.ss, h->peer.len);
last_send = now;
```

**风险分析**:
- `sendto` 返回 < 0 表示内核 UDP 缓冲区满（正常高峰期）、fd 已关闭（HA peer 重启后 fd 被上层 close 但 ha 模块还不知道）、或 `EMSGSIZE` 包太大
- 丢弃返回值的后果：
  1. **心跳发送失败不重试** — UDP 缓冲区满时心跳被丢，peer 收不到 → ha 超时后判定 peer dead → **主备切换抖动**
  2. **fd 已关闭不知道** — 上层调用 close(h->fd) 后 ha 心跳循环还在 sendto → -1 EBADF 被丢弃 → ha 永远不知道自己 fd 已经失效
  3. **`last_send = now` 无条件更新** — 心跳实际没发出去但本地计数器认为发了 → 心跳间隔计算失真

**建议**:
```c
ssize_t sent = sendto(h->fd, pkt, (size_t)n, MSG_NOSIGNAL,
                      (struct sockaddr *)&h->peer.ss, h->peer.len);
if (sent < 0) {
    llog(LOG_WARN, "ha", "heartbeat sendto failed errno=%d peer=%s",
         errno, h->node_id);
} else {
    last_send = now;
}
```
3 行改动。关键点：sendto 失败时**不要更新 last_send**，让下次心跳按原始间隔重试。

## 🟡 Medium 级

### R-08: b2bua re-INVITE `(void)send_invite_b` — 返回值被丢弃

**位置**: `src/sip/b2bua.c:7148`

```c
} else {
    /* B 腿 refresher → send_invite_b 朝 Bob 发 re-INVITE */
    (void)send_invite_b(c, 1, other->offer, other->offer_len, 1, NULL);
}
```

**风险分析**:
- `send_invite_b` 返回 `int`（NSBC_OK/NSBC_ERR）
- re-INVITE 失败的典型场景：Bob 腿已关闭（hangup_by=B_UA）、Offer SDP 构造失败、媒体端口不可用
- 丢弃返回值后 b2bua 不知道 re-INVITE 失败 → Alice 腿可能还在 bridge 但 Bob 腿的媒体已经断了 → **单通**（Alice 听得到 Bob，Bob 听不到 Alice）
- 这是**per-call 路径**，每腿 re-INVITE 都走这里

**建议**: 至少在失败时打 LOG_WARN：
```c
int rc = send_invite_b(c, 1, other->offer, other->offer_len, 1, NULL);
if (rc != NSBC_OK) {
    llog(LOG_WARN, "b2bua", "re-INVITE Bob failed rc=%d call=%s",
         rc, call->cid);
}
```
2 行改动。比 HA 心跳优先级低（单通 vs 主备抖动），但同样是静默失败。

## 🔵 Low 级

### R-09: Cargo.toml axum `http2` feature 冗余

**位置**: `web/Cargo.toml:17` + `web/Cargo.toml:25`

```toml
# line 17
axum = { version = "0.7", ..., features = ["http1", "http2", "json", ...] }
# line 25
hyper = { version = ">=1.1.0, <2", features = ["server", "http1"] }
```

**问题**: axum 开了 `http2` feature，但 main.rs **显式只用了 http1 构建器**：
- `axum::serve(...).http1().header_read_timeout(...).build()` — 强制 http1
- `hyper::server::conn::http1::Builder::new()` — TLS handler 也是 http1
- hyper crate **没有开 http2 feature** → 即使 axum 想开也开不了

**影响**: 无功能 bug，但编译体积多 ~200KB（http2 huffman table + HPACK 编解码），编译时间多 ~3s。

**建议**: 从 axum features 里去掉 `"http2"`。Web 管理端流量都是短连接管理操作，HTTP/2 头部压缩收益可忽略。

### R-10: 初始化路径 `.ok()` 吞错误（2 处）

**位置**: `main.rs:350` + `uds_server.rs:57`

```rust
// main.rs:350 — log parent dir
std::fs::create_dir_all(parent).ok();

// uds_server.rs:57 — UDS socket parent dir
std::fs::create_dir_all(parent).ok();
```

**风险分析**:
- 都是**启动初始化路径**，不是请求热路径
- create_dir_all 失败的典型原因：权限不足 / 只读文件系统 / 路径太长
- 后续写日志/创建 socket 会失败 → 有其他错误路径会 catch，但**错误消息不直接指向根因**（比如日志目录不可写 → 后面 log 文件 open 失败 → 用户看到的是 "log write failed" 而不是 "create_dir_all failed permission denied"）

**建议**: 改成 `if let Err(e) = ... { tracing::warn!("create_dir_all {parent}: {e}"); }`，一行改动。不是立即需要修，但提升诊断质量。
